  ## 🧩 Mini 最小可用版本 — 模块规划

  基于对当前 src/ 2,305 文件、packages/ 12 包的完整依赖链追踪，我按调用链路分层规划如下：

  ———

  ### 设计原则

  - Headless/pipe mode only — 无 Ink UI、无 React 组件树，单次 prompt → 多轮 tool loop → 输出结果
  - Anthropic firstParty only — 砍掉 OpenAI/Gemini/Grok/bedrock/vertex 全部分支
  - 6 个核心工具 — Bash, FileRead, FileWrite, FileEdit, Grep, Glob
  - 零 feature flag — 不依赖 bun:bundle，所有功能硬开启
  - 零遥测 — 无 OTel/Sentry/GrowthBook/analytics

  ———

  ### 保留模块清单（11 层，约 60-80 个文件）

  🟢 Tier 1: 核心调用管道（不可删）

  | 文件 | 说明 |
  |------|------|
  | src/entrypoints/cli.tsx | 简化为直走默认路径，砍掉 12 条快速路径分支 |
  | src/entrypoints/init.ts | 精简为 config load + trust 检查 |
  | src/main.tsx | 大幅精简 Commander CLI，只保留核心 .action() |
  | src/query.ts | 核心 API 查询，砍掉 compaction/hooks/autonomy/contextCollapse |
  | src/QueryEngine.ts | 精简的对话轮次编排器 |
  | src/services/api/claude.ts | Anthropic API 客户端，砍掉非 firstParty 分支 |
  | src/services/api/errors.ts | API 错误分类 |
  | src/services/api/withRetry.ts | 重试逻辑 |
  | src/services/api/emptyUsage.ts | 用量空值常量 |

  🟢 Tier 2: 上下文与会话状态（不可删）

  | 文件 | 说明 |
  |------|------|
  | src/bootstrap/state.ts | 砍掉 OTel/Metrics/Loggers 字段，保留核心状态 |
