# 第一章：项目概览与架构总览

## 1.1 什么是 Claude Code CLI

Claude Code CLI 是 Anthropic 推出的终端编程助手。用户在终端中输入自然语言指令，Claude 便能理解上下文、读写文件、执行命令、创建分支、提交代码——像一个坐在终端里的结对程序员。

但与其他 AI 编程助手不同，Claude Code 并非一个简单的"聊天窗口+代码补全"。它是一个**自主 Agent 系统**：能够理解复杂任务、分解步骤、调用工具、观察结果、迭代调整，直至目标完成。它的终端界面是基于 React 的实时渲染（Ink 框架），而非简单的文本流——这意味着它可以展示进度条、交互式权限提示、富文本消息等复杂 UI。

## 1.2 整体架构鸟瞰

从最高层看，Claude Code 的架构分为六个层次：

```
┌─────────────────────────────────────────────────────────┐
│                    入口层 Entry                          │
│        cli.tsx → main.tsx (Commander.js CLI 定义)       │
├─────────────────────────────────────────────────────────┤
│                    引导层 Bootstrap                      │
│  状态初始化 / Feature Flag 解析 / 配置加载 / 认证检查    │
├─────────────────────────────────────────────────────────┤
│              核心循环层 Core Loop                        │
│  REPL Screen → Query Engine → query() → API → 工具循环  │
├─────────────────────────────────────────────────────────┤
│                     API 层                               │
│  Claude (firstParty) / Bedrock / Vertex / OpenAI / ...  │
├─────────────────────────────────────────────────────────┤
│                    工具系统 Tool System                   │
│  60+ 内置工具 (文件/Shell/Agent/Web/MCP/...)             │
├─────────────────────────────────────────────────────────┤
│                    UI 层 Ink                              │
│  149 个组件 / 主题系统 / 虚拟滚动 / 权限弹窗              │
└─────────────────────────────────────────────────────────┘
```

每一层都有明确的职责，层间通过类型化的接口通信。

## 1.3 技术栈

| 技术 | 用途 | 备注 |
|------|------|------|
| **Bun** | 运行时 + 打包器 | 非 Node.js，import、build、test 全部使用 Bun API |
| **TypeScript** | 开发语言 | Strict 模式，tsc 零错误要求 |
| **Ink** | 终端 UI 框架 | 基于 React 的终端渲染，`packages/@ant/ink/` 是 fork 版 |
| **Commander.js** | CLI 参数解析 | 注册 20+ 子命令 |
| **Anthropic SDK** | API 通信 | 流式 SSE、tool use、thinking |
| **Biome** | Lint + 格式化 | 替代 ESLint + Prettier |
| **Zustand** | 状态管理 | AppState 的 createStore |

## 1.4 Feature Flag 系统

Claude Code 有 65+ 个 feature flag，控制从核心功能到实验特性的所有开关。这是系统中最重要的架构决策之一。

**工作方式**：代码中通过 `import { feature } from 'bun:bundle'` 导入，调用 `feature('FLAG_NAME')` 返回 boolean。Bun 的编译器要求在 `if` 语句或三元表达式条件位置使用，不能赋值给变量。

**三个层面的控制**：

- **Dev 模式**（`bun run dev`）：默认全部启用
- **Build 模式**（`bun run build`）：通过 `DEFAULT_BUILD_FEATURES` 选择启用
- **运行时**：环境变量 `FEATURE_<FLAG_NAME>=1` 覆盖

**Flags 的分类**：

- **基础功能**：BUDDY、VOICE_MODE、BRIDGE_MODE
- **P0 本地**：AGENT_TRIGGERS、ULTRATHINK、LODESTONE
- **P1 API 依赖**：EXTRACT_MEMORIES、VERIFICATION_AGENT、KAIROS_BRIEF
- **工作流**：WORKFLOW_SCRIPTS、MONITOR_TOOL、HISTORY_SNIP
- **多 Agent**：COORDINATOR_MODE、BG_SESSIONS、FORK_SUBAGENT
- **已禁用**：CONTEXT_COLLAPSE、FORK_SUBAGENT、SKILL_LEARNING

这个系统的设计哲学是：**代码永远存在，但运行时决定启用什么**。新功能以 feature flag 合入主干，逐步灰度，最终全量开放后移除 flag。

## 1.5 模块与包结构

项目是 Bun workspace 单仓（monorepo），主包 + 17 个 workspace packages：

| 级别 | 包 | 职责 |
|------|----|------|
| 核心 | `src/` | 主应用代码 ~2300 文件 |
| UI | `packages/@ant/ink/` | Fork 版 Ink 框架 |
| 工具 | `packages/builtin-tools/` | 60 个内置工具 |
| Agent | `packages/agent-tools/` | Agent 相关工具与类型 |
| 原生 | `packages/*-napi/` | 音频/图像/颜色/键盘等原生能力 |
| 远程 | `packages/remote-control-server/` | 自托管 RCS |
| MCP | `packages/mcp-client/` | MCP 客户端库 |
| 桥接 | `packages/acp-link/` | ACP 协议桥接 |

## 1.6 构建与发布

构建入口是 `build.ts`，执行 `Bun.build()` 进行代码分割，输出 `dist/cli.js` + chunk 文件。构建时会：

1. 注入 Feature Flag 的 define 常量
2. 自动替换 `import.meta.require` 为 Node.js 兼容版本
3. 复制 vendor 二进制文件（audio-capture、ripgrep）到 `dist/vendor/`

产物同时兼容 Bun 和 Node.js 运行。

## 1.7 入口流程

启动时，`cli.tsx` 的 `main()` 函数按优先级处理多条快速路径：

1. `--version` / `-v` — 零模块加载，瞬时返回
2. `--dump-system-prompt` — 仅当 feature 启用
3. `--claude-in-chrome-mcp` / `--computer-use-mcp` — 独立 MCP server 模式
4. `daemon` 子命令 — 长驻 supervisor 模式
5. 模板任务命令：`new` / `list` / `reply`
6. **默认路径**：加载 `main.tsx` 启动完整 CLI

默认路径会初始化 Commander.js 注册所有子命令，然后运行 `.action()` 处理器。处理器负责权限检查、MCP 连接、会话恢复等，最终进入 REPL 屏幕。
