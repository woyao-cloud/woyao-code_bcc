# 第 1 章：项目概览与架构总览

## 1.1 项目背景

Claude Code 是 Anthropic 开发的 AI 编程助手 CLI 工具。mini-v9 项目是一个经过逆向工程恢复的精简版本，保留了完整的 Agent 驱动交互架构。项目的核心设计目标可以归纳为：

- **Agent 驱动**：以 LLM 为核心的自主决策循环，而非简单的问答模式
- **工具增强**：60+ 内置工具让 Agent 能够读写文件、执行命令、搜索代码、浏览网页
- **持久会话**：支持跨会话记忆、长对话上下文管理、项目级配置
- **多 Agent 协作**：支持子 Agent 分支执行、团队成员协作、并发任务

## 1.2 整体架构分层

从软件架构角度看，项目可以划分为以下层次：

### 表现层（Presentation Layer）
终端 UI 层基于 Ink 框架（一个用 React 渲染终端的框架）构建。核心是 REPL 屏幕组件，负责渲染对话消息、工具调用状态、权限提示浮层等。所有 UI 组件位于 `src/components/` 目录下，总计约 150 个组件。

### 协调层（Orchestration Layer）
这是系统的核心大脑，由 QueryEngine 类驱动。它负责任务的完整生命周期：接收用户输入、构建 API 请求参数、发送流式请求、解析模型响应、调度工具执行、收集执行结果、决定是否需要下一轮。这一层包含最重要的设计决策：如何组装 System Prompt、如何管理 Context 窗口、如何处理错误和重试。

### 能力层（Capability Layer）
提供 Agent 可调用的各种能力：
- **工具系统**：60 个内置工具，注册在统一的工具注册表中
- **Agent 系统**：多种预定义 Agent（探索 Agent、规划 Agent、Claude 指南 Agent 等）
- **MCP 连接器**：通过 MCP 协议调用外部工具服务器
- **多 Provider 支持**：Anthropic First Party、AWS Bedrock、Google Vertex、OpenAI 兼容层、Gemini、Grok

### 基础设施层（Infrastructure Layer）
提供支撑上层运行的通用能力：
- **Context 管理**：System Prompt 分节组装、对话历史折叠、Token 预算控制、Prompt Cache 管理
- **Memory 体系**：跨会话持久化记忆、memdir 目录结构、自动提取与巩固
- **Hooks 系统**：生命周期钩子（SessionStart/SessionEnd/PreQuery/PostQuery 等）
- **配置系统**：CLAUDE.md 项目级指令、全局设置、特性开关
- **埋点/日志**：事件追踪、性能指标、调试日志

## 1.3 技术栈速览

| 领域 | 技术选型 |
|------|---------|
| 运行时 | Bun (非 Node.js) |
| 语言 | TypeScript + TSX (React JSX) |
| 终端渲染 | Ink (自维护 fork，位于 packages/@ant/ink/) |
| 构建工具 | Bun.build() 代码分割 + 可选 Vite 构建 |
| API SDK | @anthropic-ai/sdk |
| 测试框架 | bun:test (内置) |
| Lint/Format | Biome |
| 消息格式 | Anthropic Messages API |
| 流式协议 | SSE (Server-Sent Events) |
| 状态管理 | Zustand 风格 Store |
| Provider 协议 | Anthropic Messages API (所有第三方 API 均适配为此格式) |

## 1.4 目录结构

项目采用 monorepo 结构，核心源码在 `src/` 目录下，关键包分布在 `packages/` 下：

```
src/
├── entrypoints/cli.tsx    # 真正入口，处理快速路径
├── main.tsx               # Commander.js CLI 定义 (5674 行)
├── query.ts               # 核心 API 查询函数 (LLM 交互主干)
├── QueryEngine.ts         # 高级编排器 (消息/Token/状态管理)
├── context.ts             # 上下文构建
├── Tool.ts                # 工具接口定义
├── tools.ts               # 工具注册表装配
├── services/
│   ├── api/               # API 层 (claude.ts + 6 个兼容层)
│   ├── compact/           # 上下文折叠/压缩
│   ├── memory/            # 记忆系统
│   └── searchExtraTools/  # 延迟工具搜索
├── components/            # Ink UI 组件
├── state/                 # 应用状态管理
├── types/                 # 类型定义
├── utils/                 # 通用工具函数
└── bootstrap/             # 启动初始化
```

## 1.5 关键设计决策

### 为何选择 Bun 而非 Node.js？
Bun 提供了内置的 TypeScript 支持、快速的依赖解析、内置的测试框架和打包器。项目使用 Bun.build() 进行代码分割构建，使用 `bun:bundle` 模块的 `feature()` 函数实现编译时特性开关。构建产物经过后处理可以兼容 Node.js 运行。

### 为何选择 Ink 框架？
Ink 允许使用 React 组件模型渲染终端 UI，实现了声明式的组件树、状态驱动的重渲染、以及组件生命周期管理。项目 fork 了内部版本的 Ink，进行了深度定制。

### 为何有多 Provider 支持？
项目设计为 Provider 无关的架构。所有第三方 API（OpenAI、Gemini、Grok、AWS Bedrock、Google Vertex）都通过流适配器模式转换为 Anthropic 内部消息格式，下游代码完全不感知 Provider 差异。这使得用户可以根据需求选择不同的后端模型。

### 特性开关系统
项目使用编译时特性开关（Feature Flag），通过 Bun 的 `-d` 参数注入 MACRO 定义。代码中统一通过 `feature('FLAG_NAME')` 调用。Dev 模式默认启用全部特性，Build 模式选择 65+ 个特性启用，其余关闭。这是项目"恢复核心功能、裁剪次要能力"策略的体现。

## 1.6 启动流程

当用户在终端输入 `claude` 时，以下是完整的启动链路：

1. **cli.tsx** 入口被调用，`main()` 函数按优先级检查快速路径
2. 快速路径包括：`--version`、`--dump-system-prompt`、MCP 模式、Daemon 模式、远程控制模式等
3. 如果无匹配快速路径，加载 `src/main.tsx` 启动完整 CLI
4. Commander.js 注册大量子命令（mcp、server、auth、plugin、agents 等）
5. 主 `.action()` 处理器执行初始化：加载配置、检查认证、设置 MCP 连接、恢复会话
6. 最终分发到 REPL 模式（交互式）或 Headless 模式（单次执行）
7. REPL 模式渲染 Ink React 树，用户看到完整的终端界面

## 1.7 本书的阅读方法

第 2 章是全书最核心的一章，详细描述了 Agent 运行循环的每一步设计。建议所有读者优先阅读。后续章节可以按兴趣选择阅读，第 3 章（Context 管理）和第 6 章（C 端体验优化）直接相关，第 4 章（Memory 体系）和第 7 章（多 Agent 协作）相对独立，第 5 章（埋点）适合关注可观测性的读者，第 8 章（全链路追踪）是对前面所有章节的综合性串联。
