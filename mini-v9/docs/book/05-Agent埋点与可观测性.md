# 第 5 章：Agent 埋点与可观测性

## 5.1 概述

在一个复杂的 Agent 系统中，了解"发生了什么"和"为什么发生"同样重要。埋点与可观测性体系确保开发者（和评测团队）能够追踪 Agent 的行为、诊断问题、分析性能。

项目的可观测性体系包含四个层次：
- **事件追踪**：记录关键用户行为和系统事件
- **性能指标**：测量延迟、Token 使用等量化指标
- **调试日志**：细粒度的运行时信息
- **遥测导出**：将数据导出到外部分析系统

## 5.2 事件追踪体系

### 事件分类

系统定义了一系列标准化事件，覆盖用户交互的全生命周期：

**用户行为事件**：
- 会话开始/结束
- 用户输入提交
- 权限授予/拒绝
- 设置修改
- 命令执行

**系统生命周期事件**：
- 启动/关闭
- 初始化完成
- 配置加载
- 认证状态变更

**Agent 行为事件**：
- Agent 循环开始/结束
- 工具调用请求
- 工具执行完成
- API 请求/响应
- 上下文压缩触发

**错误事件**：
- API 错误（分类为重试可/不可）
- 工具执行失败
- 权限拒绝
- 超时

### 事件格式

所有事件遵循统一的结构化格式，包含：
- `type`：事件类型标识符
- `timestamp`：事件发生时间（ISO 8601）
- `sessionId`：关联的会话 ID
- `properties`：事件特定的属性载荷
- `tags`：可选的标签列表（用于过滤和聚合）

### 事件管道

事件从产生到消费经过以下管道：

1. **发射**：在代码的关键节点（API 请求、工具调用、异常捕获处）调用事件发射函数
2. **缓冲**：事件先进入内存缓冲区（默认 100 条上限），避免高频场景下的大量同步 I/O
3. **处理**：注册的事件处理器按优先级依次处理
4. **导出**：经过格式化和批处理后，导出到外部系统

## 5.3 性能指标体系

### 关键指标

系统跟踪以下性能指标：

**延迟指标（Latency Metrics）**：
- 首 Token 延迟（TTFT）：从发送请求到收到第一个 Token 的时间
- 单轮交互延迟：从发送请求到收到完整响应的时间
- 工具执行延迟：每个工具的执行时间
- 整体会话延迟：会话的总耗时

**资源指标（Resource Metrics）**：
- Token 使用量（输入/输出/缓存读/缓存写）
- API 调用次数
- 工具调用次数和分布
- Context 窗口使用率

**质量指标（Quality Metrics）**：
- 缓存击中率（cache_hit_rate）
- API 重试率
- 工具失败率
- 权限拒绝率

### 指标聚合

指标在会话级别聚合，提供以下视图：
- **实时视图**：当前会话的即时状态（状态栏展示）
- **会话视图**：会话结束后的统计摘要
- **累计视图**：跨会话的累计统计

### 成本追踪

项目实现了 CostTracker，实时追踪 API 调用的美元成本：
- 基于模型的 Token 定价表计算
- 支持按会话/按轮次的成本查询
- 支持设置预算上限，超过时自动终止
- 在 UI 中实时展示成本信息

## 5.4 调试日志系统

### 日志层级

日志系统采用标准的分级体系：
- `error`：严重影响功能的错误（API 故障、系统异常）
- `warn`：需要关注但不影响功能的问题（配置不完整、降级运行）
- `info`：正常运行状态信息（启动完成、会话开始）
- `debug`：细粒度的调试信息（中间状态、变量值）

### 日志存储

调试日志的存储方式根据不同运行模式而不同：
- **CLI 模式**：日志写入标准错误流，不干扰正常输出
- **文件模式**：通过环境变量启用时，日志写入指定目录的文件
- **ACP 模式**：代理服务器使用 pino 日志库，同时输出到文件和控制台

### 日志过滤

为避免日志爆炸，系统实现了过滤机制：
- **级别过滤**：只记录 >= 设定级别（默认 info）的日志
- **去重过滤**：短时间内重复的相同日志被合并
- **大小限制**：日志文件超过阈值时回滚

## 5.5 遥测导出

### BigQuery 导出

系统支持将事件和指标导出到 Google BigQuery：
- 数据点（DataPoint）结构包含时间戳、名称、值、标签
- Metric 结构聚合同类数据点
- 导出为批量操作，减少 API 调用次数

### 导出策略

- **批处理**：积累一定数量的事件后统一导出（避免高频单条导出）
- **节流**：受限于外部 API 的速率限制
- **隐私控制**：可配置的导出粒度，支持关闭个人身份信息的导出

## 5.6 Perfetto 追踪

对于多 Agent 协作场景，系统集成了 Perfetto 追踪支持：
- 每次 Agent 生成/销毁时注册追踪事件
- 形成 Agent 调用树的可视化
- 在调试模式下可以通过 Perfetto UI 查看

每个 Agent 在 Perfetto 中注册时包含：
- Agent ID（唯一标识）
- Agent 名称
- 父会话 ID（形成树状结构）
- 创建时间戳

## 5.7 评估与测试支持

### 标准化输出格式

系统确保所有关键事件的输出格式是标准化的，以便评测团队编写自动化测试：
- API 请求/响应的结构化日志
- 工具调用/结果的一致性格式
- 错误信息的分类和标准化

### 可重现性

为了支持回归测试，系统提供了：
- 确定性种子支持（用于随机数生成）
- 时间戳 Mock 支持
- 外部 API 调用的录制/回放机制

## 5.8 设计权衡总结

| 维度 | 方案 | 考量 |
|------|------|------|
| 事件粒度 | 重要节点 + 可配置 | 粒度太细则日志爆炸，太粗则无法诊断 |
| 日志存储 | 标准错误 + 文件 | 文件可靠但需要磁盘空间 |
| 遥测导出 | BigQuery | 强依赖外部服务，离线时降级 |
| 性能影响 | 异步 + 批处理 | 尽量减少对主流程的性能影响 |
| 隐私控制 | 可配置导出级别 | 用户信任与数据价值之间的平衡 |
