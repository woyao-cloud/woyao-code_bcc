# 第 4 章：Memory 体系与个性化配置

## 4.1 概述

一个没有记忆的 AI 助手，每次对话都是从零开始的。为了让 Claude Code 能够"记住"用户的偏好、项目的配置、历史的上下文，项目构建了一套完整的 Memory 体系。

Memory 体系由四个子系统组成：
- **文件级记忆（Memdir）**：基于文件目录的持久化存储
- **记忆提取与巩固**：从对话中自动提取关键信息
- **Hooks 系统**：事件驱动的生命周期钩子
- **项目级指令注入（CLAUDE.md）**：项目级别的配置与指令

## 4.2 Memdir：文件级记忆系统

### 存储结构

Memdir 是一个基于文件系统的记忆存储方案。它以目录结构和 Markdown 文件为存储单元，按照"范围 × Agent 类型"的二维组织方式存储记忆：

```
~/.claude/agent-memory/         # 用户级记忆（跨项目）
  ├── claude/                    # Agent 类型目录
  │   ├── preferences.md         # 一个记忆文件
  │   └── workflow.md
  └── explore-agent/             # 探索 Agent 的记忆目录
      └── search_patterns.md

<project>/.claude/agent-memory/  # 项目级记忆（项目内共享）
  └── claude/
      └── project-context.md

<project>/.claude/agent-memory-local/ # 本地级记忆（仅当前机器）
```

### 三层作用域

Memdir 将记忆划分为三个作用域，优先级从低到高：

1. **用户级（user）**：存储在 `~/.claude/agent-memory/`，跨项目、跨会话持久化。适合存储用户的通用偏好和习惯。
2. **项目级（project）**：存储在 `<project>/.claude/agent-memory/`，项目目录内共享（通常纳入版本控制）。适合存储项目特有的配置和约定。
3. **本地级（local）**：存储在 `<project>/.claude/agent-memory-local/`，不纳入版本控制。适合存储本地机器特有的配置。

### 扫描与加载

在每一轮交互开始时，系统会扫描三个作用域的 memdir 目录，收集所有 `.md` 文件。扫描逻辑是递归的：先扫描用户级目录，再扫描项目级和本地级目录。每个文件都会被读取、解析并记录元数据（文件大小、修改时间、作用域类型）。

扫描到的记忆文件内容会通过 System Prompt 的"记忆"节注入到上下文中。如果同时加载多个记忆文件，系统会按作用域和修改时间排序，优先展示最新的记忆。

### 记忆命令

项目提供了 CLI 命令让用户直接操作记忆：
- `memory add`：添加一条新记忆（指定内容、标签、分类）
- `memory list`：列出所有记忆
- `memory search`：关键词搜索记忆内容

这些命令绕过了自动提取的流程，允许用户显式地"教"Agent 记住某些事情。

## 4.3 自动记忆提取与离线巩固

### 提取机制

除了用户主动存储的记忆，系统还具备**自动记忆提取**能力。它在对话的后台（通过 post-sampling hook）运行，分析每一轮对话的内容，自动提取出值得记忆的信息。

提取过程由 ExtractMemories 模块驱动：
1. **触发条件**：每轮对话完成后，如果对话超过一定轮次（如 2 轮以上），触发记忆提取
2. **提取方式**：将对话内容发送给 LLM（使用轻量级 Fork），让其总结出"值得记住"的信息
3. **提取内容**：包括用户偏好、工作流模式、项目约定、常用命令等
4. **存储**：提取出的记忆被写入 memdir 文件

### 离线巩固

记忆提取后不会立即影响 Agent 行为，而是进入"巩固"阶段：
1. 提取出的记忆被写入 memdir 的临时文件
2. 在下一轮对话的 System Prompt 组装时，这些记忆文件被扫描并加载
3. 如果多次观察到相同的记忆模式，系统会提升其优先级

### 记忆的时效性

记忆文件带有修改时间戳。系统在加载记忆时会考虑时效性：
- 最近的记忆优先级更高
- 过旧的记忆可能被自动裁剪（默认 7 天保留期）
- 用户可以通过 CLI 命令显式删除或编辑记忆

### 穷鬼模式下的降级

当用户启用"穷鬼模式"（/poor 命令）时，记忆提取被完全跳过。这是一种 Token 节省策略，适用于预算敏感的场景。

## 4.4 Hooks 系统

### 设计理念

Hooks 系统是项目的事件驱动扩展点。它允许用户在 Agent 的生命周期中插入自定义行为，而不需要修改项目代码。Hooks 系统是"个性化配置"的核心基础设施。

### Hook 事件类型

系统定义了多种生命周期事件，每种事件对应 Agent 运行的一个阶段：

```
SessionStart     → 会话开始时触发
Setup            → 初始化设置时触发
PreQuery         → 发送请求到 API 前触发
PostQuery        → API 请求完成后触发
PreToolUse       → 工具执行前触发
PostToolUse      → 工具执行后触发
SessionEnd       → 会话结束前触发
```

每个事件都可以注册多个处理器，处理器按注册顺序执行。

### Hook 注册方式

Hooks 可以通过三种方式注册：

1. **配置文件（settings.json）**：用户可以在全局或项目的 settings.json 中配置 hook 命令。例如配置在 PreQuery 事件中执行一个脚本。
2. **Session Hooks**：运行时可编程添加的钩子，仅当前会话有效。例如 SDK 模式下注册的临时检查钩子。
3. **Function Hooks**：纯内存执行的回调函数，用于结构化输出验证等场景。有超时机制（默认 5 秒）。

### Hook 执行流程

当某个事件触发时，系统按以下流程执行 Hook：
1. 从配置中获取该事件的所有注册 Hook（包括快照配置、会话 Hook、功能 Hook）
2. 检查 Hook 的匹配器（matcher），只有匹配当前上下文的才执行
3. 按顺序执行匹配的 Hook
4. 收集执行结果（stdout、stderr、退出码）
5. 如果 Hook 失败（超时、非零退出码），根据配置决定是否阻断主流程

### Post-Sampling Hooks

Post-Sampling Hooks 是一个特殊的 Hook 类别——它们在模型采样完成后、结果提交给用户之前执行。这些 Hook 不通过 settings.json 配置，而是通过编程接口注册。典型用途包括：
- 记忆提取（分析对话内容并存储记忆）
- Prompt 建议生成（在用户输入后生成建议）
- 技能学习（分析用户行为模式）

### Hook 事件系统

系统提供了一个事件发射器（HookEvents），用于广播 Hook 的执行状态：
- `started`：Hook 开始执行
- `progress`：Hook 执行中的中间输出（以间隔轮询方式获取）
- `response`：Hook 执行完成（成功/失败/取消）

这些事件可以被注册的 Handler 消费，例如转换为 SDK 消息或写入日志。

## 4.5 CLAUDE.md：项目级指令注入

### 设计理念

CLAUDE.md 是项目级的行为配置文件，位于项目根目录。它允许项目团队为 AI 助手编写定制的工作指令，类似于项目的 README，但专为 AI 助手设计。

### 文件发现与加载

系统启动时，ClaudeMd 模块会从项目目录开始向上搜索 CLAUDE.md 文件。搜索路径包括：
- 项目根目录
- 项目 `.claude/` 子目录
- 用户 `~/.claude/` 目录

多层 CLAUDE.md 会按从外层到内层的顺序合并，内层内容覆盖外层。

### 内容注入

CLAUDE.md 的内容通过 System Prompt 的 "claudeMd" 节注入到上下文中。注入时遵循以下规则：
- **优先级排序**：项目级 > 用户级
- **长度控制**：超过最大长度时被截断
- **动态加载**：文件修改后自动刷新（通过文件修改时间检测）

### CLAUDE.md 与 Memdir 的区别

两者都是项目级配置的载体，但有明确分工：
- **CLAUDE.md**：适合声明式配置——编码规范、项目结构、技术栈、行为约束。一次编写，全局有效。
- **Memdir**：适合动态记忆——用户偏好、工作习惯、历史决策。由系统自动提取或用户按需添加。

## 4.6 个性化学习与用户偏好

### 技能学习系统

项目包含一个实验性的技能学习子系统（SkillLearning），它通过运行时观察用户的交互模式来动态学习。学习过程：
1. **观察**：在 Post-Sampling Hook 中分析对话模式
2. **发现**：检测重复出现的用户指令模式
3. **固化**：将发现的模式转化为可复用的记忆

### Prompt 建议

系统通过 PromptSuggestion 模块生成下一轮输入的建议。它基于：
- 对话上下文中的当前状态
- 用户的历史输入模式
- 任务完成度评估

建议生成同样通过 ForkedAgent 在后台运行，不阻塞主流程。

### 个性化阈值控制

系统根据用户的交互行为自动调整以下参数：
- 自动压缩触发阈值
- 记忆提取频率
- Token 预算分配优先级

这些调整通过记录用户的交互历史（如平均会话长度、常用工具类型）来动态计算。

## 4.7 设计权衡总结

| 维度 | 方案 | 考量 |
|------|------|------|
| 记忆存储 | 文件系统（非数据库） | 无需依赖外部服务，版本控制友好，但大规模时查询性能有限 |
| 记忆作用域 | 三层隔离 | 灵活但增加了系统复杂度，需要多级扫描 |
| 自动提取 | 后台异步执行 | 不阻塞主流程但可能延迟生效，且消耗额外 Token |
| Hooks 配置 | settings.json + 程序化注册 | 灵活但可能有安全风险（任意命令执行） |
| CLAUDE.md vs Memdir | 声明式 vs 动态式 | 两者互补但边界模糊，用户可能混淆 |
