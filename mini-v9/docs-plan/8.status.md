当前代码是"反应式压缩"(reactive compaction)，不是"阶段式渐进折叠"(staged progressive folding)。

  两者的关键区别：

  ┌────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────────────────┐
  │    方面    │                        当前实现                        │                             阶段式折叠                             │
  ├────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤
  │ 触发时机   │ 遇到 prompt_too_long 错误后 / 预估下一轮会超限时       │ 持续监控，在多个水位线提前渐进处理                                 │
  ├────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤
  │ 折叠粒度   │ 一次性压缩，策略递进（llm → micro → keepPairs → drop） │ 按阶段逐步加深折叠程度                                             │
  ├────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤
  │ 上下文保留 │ 只保留最近 N 轮，之前的全部压缩/丢弃                   │ 按距当前距离分层处理（最近 verbatim、稍远 summary、更远 abstract） │
  └────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────────────────┘

  当前已有的类阶段式能力：
  - query.ts:106-118 的预测性自动压缩(predictive autocompact) — 当 estimatedHeadroom < growthEstimate 时提前触发 compact，算是半个阶段式
  - reactiveCompact.ts 的多级策略(step 0→5) — 逐级尝试更激进的策略

  缺失的完整阶段式折叠应该包含：

  1. 多水位线监控 — 在 context 使用率达到 40%/60%/80% 时分别触发不同策略
  2. 按距离分层 — 最近的 N 轮保持原样，中间的 M 轮做 LLM summary，更早的做 keyword-level abstract
  3. 渐进加深 — 不是一次性把 0→5 跑完，而是每次只进一级，随着 conversation 增长逐步加深
  4. 后台异步折叠 — 非阻塞地在每轮结束后对旧消息进行 summary 预处理
