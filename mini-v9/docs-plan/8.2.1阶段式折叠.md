 2. MODIFY src/query.ts — Error Withholding + 4-Stage Recovery

 Error withholding (during streaming)

 In the streaming event processing loop, when an assistant message arrives that is a PTL/media/max_tokens error, do NOT yield it to the consumer yet — push it to
 assistantMessages for recovery checks.

 // In the message_delta or error handler:
 let withheld = false
 if (reactiveCompact.isWithheldPromptTooLong(message)) {
   withheld = true
 }
 if (reactiveCompact.isWithheldMediaSizeError(message)) {
   withheld = true
 }
 if (isWithheldMaxOutputTokens(message)) {
   withheld = true
 }
 if (!withheld) {
   yield yieldMessage
 }

 4-stage recovery flow (after stream ends, before tool processing)

 After streaming completes and no tool_use blocks are found:

 Stage 1 — Collapse drain (if available): Cheap, keeps granular context. Drain staged context collapses to free space. If enough freed, retry immediately.

 Stage 2 — Reactive compact: Summarize and compact conversation. If successful, retry. Already exists in mini-v9 but needs to be wired into the new flow.

 Stage 3 — Max tokens escalation: If the error is max_output_tokens and the cap was default (32K), retry with escalated (64K) — no meta message needed.

 Stage 4 — Max tokens recovery: Insert recovery meta-message and let the model continue. After 3 attempts with diminishing returns detection, surface the error.

 Each stage yields appropriate events for the UI to show feedback.
