# UI/渲染层差距分析

## 现状

mini-v8 使用 **纯 readline** CLI (`src/entrypoints/cli.ts`)。完整版使用 **Ink/React** (`packages/@ant/ink/`) 渲染引擎 + 412 个组件文件。

## 关键差距

| 特性 | 完整版 | mini-v8 |
|------|--------|---------|
| 渲染引擎 | Ink (packages/@ant/ink/) | 纯 readline |
| 消息渲染 | 彩色，多行，语法高亮 | 纯文本 stdout |
| 权限弹窗 | React 组件 (16+ 权限类型) | 简单 readline 提问 |
| 输入框 | PromptInput (语法高亮，多行) | readline.question |
| 快捷键 | 完整按键绑定系统 (15 文件) | 不支持 |
| 状态栏 | StatusLine (实时信息) | 不支持 |
| Spinner | Spinner 组件 | setInterval, 简单字符 |
| 计划 UI | PlanView (进度条/状态) | 不支持 |
| 主题 | 完整主题系统 + Provider | 不支持 |

## 推荐策略

mini-v8 使用纯 CLI (无 Ink 依赖) 是对终端兼容性的取舍。建议：

1. **保持纯 CLI 路线**，不引入 Ink/React 依赖（减少 500+ 文件）
2. **渐进式增强 readline**：
   - 更好的 spinner (ora/chalk)
   - 彩色输出 (chalk)
   - 多行输入支持
   - 命令历史
3. 如需 React 渲染，可以按功能子项目引入（如 PlanView、权限弹窗）

这种策略可以避免 `packages/@ant/ink/` 的复杂依赖，同时保证核心功能可用。
