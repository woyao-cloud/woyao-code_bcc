● 对比分析结果

  主代码库 woyao-code_bcc/src/services/compact/ 有 16 个模块，mini-v8 只有 5 个。以下是 mini-v8 缺失的关键优化能力：

  ---
  Gap 1 — 服务端 cache_edits（最高价值）

  主代码库：apiMicrocompact.ts 通过 Anthropic API 的 clear_tool_uses_20250919 beta 策略，在服务端直接清除缓存中的旧 tool result，无需客户端重传。既省上行 token，又避免 prompt
   cache miss。

  mini-v8 现状：纯客户端 microcompact——修改消息内容后全量重传，每次 microcompact 都导致 cache miss。

  价值：每次 API 调用节省数千到数万 token（取决于 tool result 大小）。

  ---
  Gap 2 — 按 API round 分组

  主代码库：grouping.ts 按 assistant message.id 边界分 group，而非按人类轮次。使 reactive compact 可以在单条 agentic session（SDK/CCR 调用者）内精准裁剪。

  mini-v8 现状：不分组，reactive compact 对整个消息数组做线性裁剪。

  ---
  Gap 3 — 单独的 snip projection 模块

  主代码库：snipProjection.ts + snipCompact.ts 分离，职责清晰。

  mini-v8 现状：snipCompact.ts 混合同一文件。

  ---
  Gap 4 — 更广的 COMPACTABLE_TOOLS

  主代码库：包含 FILE_EDIT、FILE_WRITE。

  mini-v8 现状：缺少这两个高频工具的 microcompact 资格。

  ---
  Gap 5 — LLM 驱动压缩提示词模板

  主代码库：prompt.ts 提供完整的分析/摘要压缩提示词（含 NO_TOOLS_PREAMBLE、<analysis> + <summary> XML 块格式）。

  mini-v8 现状：generateCompactionSummary() 纯启发式提取，无 LLM 总结。
