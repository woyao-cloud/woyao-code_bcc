● Phase 5 优化细节

  Part A — API Round Grouping

  主代码库：grouping.ts 提供 groupMessagesByApiRound()，按 assistant message.id 边界将消息分为 API round 组。用于 compact.ts 的 truncateHeadForPTLRetry()——当 compaction
  请求本身触发 prompt_too_long 时，按整组丢弃最早的消息，而非盲目按比例裁剪。

  mini-v8 现状：无分组。reactiveCompact.ts 直接对消息数组做线性 compactMessages()。

  适配方案：BetaMessageParam 没有 message.id 字段。简化为 按 assistant 角色边界分组——每个 assistant 消息标志一个新 round 开始。对于非流式调用，这等价于 API round 分组：

  [User, Assistant, User, Assistant, User, Assistant] →
  [[User, Assistant], [User, Assistant], [User, Assistant]]

  // 新增文件: groupByApiRound.ts
  export function groupByApiRound(messages: BetaMessageParam[]): BetaMessageParam[][] {
    const groups: BetaMessageParam[][] = []
    let current: BetaMessageParam[] = []
    for (const msg of messages) {
      if (msg.role === 'assistant' && current.length > 0) {
        groups.push(current)
        current = [msg]
      } else {
        current.push(msg)
      }
    }
    if (current.length > 0) groups.push(current)
    return groups
  }

  集成到 reactive compact：当需要更激进地 compact 时，按最旧的整组丢弃而非逐条裁剪。
