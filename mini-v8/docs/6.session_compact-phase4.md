  Time-based Microcompact 规划

  现状

  microcompactToolResults() 是纯计数的：总数 > 6 才触发，保留最近 3 个，其余清空。这意味着如果会话有 20 轮但 tool result 只有 5 个（因为部分轮次没调工具），永远不会触发
  microcompact，老结果一直占着 token。

  目标

  按消息位置淘汰：即使 tool result 总数不足 6 个，位于会话"早期"的消息中的 tool result 也应该被 microcompact。

  设计方案

  在 microcompactToolResults 的 options 中新增一个参数：

  options?: {
    triggerThreshold?: number   // 计数阈值（现有，默认 6）
    keepRecent?: number         // 保留最近几个（现有，默认 3）
    positionThreshold?: number  // 新增：消息位置阈值
  }

  核心逻辑（只改 autoCompact.ts 一个文件）：

  1. 收集所有可 compact 的 tool result IDs（不变）
  2. 初始化 idsToClear 为空 Set

  3. [计数驱动] 若总数 > triggerThreshold：
     → 加入 idsToClear：除最后 keepRecent 个之外的全部 ID（不变）

  4. [时间驱动] 若设了 positionThreshold：
     → 遍历 messages，对索引 < messages.length - positionThreshold 的消息
     → 找到其中的 tool result ID，加入 idsToClear

  5. idsToClear 为空 → 返回原 messages
  6. 否则 → 执行 microcompact

  关键特性：
  - 两个机制完全独立，各自往 idsToClear Set 里追加 ID，无冲突
  - 计数驱动仍保持早期返回（<= triggerThreshold 时跳过计数逻辑），但位置驱动不受此限制
  - 位置驱动没有额外的 keepRecent —— positionThreshold 本身定义了"什么算最近"
  - 默认值 positionThreshold = 10（最后 10 条消息之外的 tool result 都 compact）
